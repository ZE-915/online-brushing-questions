# 刷题系统 - 功能设计文档

## 系统概览

刷题系统是一款全栈Web应用，支持用户通过题库进行自测、错题管理和学情分析。系统采用前后端分离架构，提供完整的题目管理、考试流程、错题追踪和背题练习功能。

**核心用户场景：**
1. 用户注册登录
2. 构建个人题库（科目/知识点/题目）
3. 自测考试（随机/知识点/错题模式）
4. 背题复习（直接查看答案和解析）
5. 错题管理（自动记录、标记、笔记）
6. 学情分析（掌握度统计）

## 模块详解

### 1. 用户认证模块 (AuthController)

#### 功能描述
提供用户注册和登录功能，使用 JWT 令牌进行身份验证。

#### 业务流程

**注册流程：**
```
用户提交注册请求 (用户名 + 密码)
  ↓
后端验证用户名唯一性
  ↓
密码加密存储到 user_account 表
  ↓
返回注册成功
```

**登录流程：**
```
用户提交登录请求 (用户名 + 密码)
  ↓
验证用户存在 + 密码正确
  ↓
JwtUtil 生成 7 天有效期的 JWT token
  ↓
前端存储 token 到 localStorage
  ↓
后续请求在 Header 中附加 "Bearer {token}"
```

#### 端点列表
| 方法 | 路径 | 功能 |
|------|------|------|
| POST | `/api/auth/register` | 注册新用户 |
| POST | `/api/auth/login` | 登录，返回 JWT token |

#### 核心操作
- 密码验证与加密（使用 Spring Security）
- JWT 令牌生成与配置（7天过期）
- 跨域请求处理（CORS）

### 2. 题库管理模块 (QuestionController + CatalogController)

#### 功能描述
管理题目、科目和知识点的完整生命周期。支持题目的增删改查、批量导入和作答状态追踪。

#### 2.1 题目 CRUD (QuestionController)

**业务流程：**

```
题目管理流程：
  
创建：用户输入题目 → 验证数据 → 存储到 question 表 → 返回题目 ID
  
查询：
  1. 列表查询 - 按关键字/题型/难度/科目/知识点筛选
  2. 显示作答状态 - 从 answer_record 表查询历史最新作答记录
  3. 状态值：1=答对、0=答错、null=未答
  
修改：查询现有题目 → 权限检查 → 更新字段 → 保存
  
删除：检查是否被其他记录引用 → 删除题目 → 同步删除关联的 answer_record
```

#### 2.2 科目和知识点管理 (CatalogController)

**数据关系：**
```
Subject (科目)
  ↓
  └─── 一对多 ──→ KnowledgePoint (知识点)
                    ↓
                    └─── 一对多 ──→ Question (题目)
```

**科目管理流程：**
- 创建科目：输入名称 + 描述 → 保存
- 编辑科目：修改名称/描述 → 更新
- 删除科目：级联删除其下所有知识点 → 问题：如果知识点有题目则 DELETE RESTRICT 失败

**知识点管理流程：**
- 创建知识点：选择科目 → 输入名称/描述 → 保存
- 编辑知识点：修改名称/描述 → 更新
- 删除知识点：如果有题目关联则报错"该知识点下有关联题目，无法删除"

#### 端点列表

**题目相关：**
| 方法 | 路径 | 功能 |
|------|------|------|
| GET | `/api/questions` | 列表（支持筛选，含作答状态） |
| GET | `/api/questions/{id}` | 查看单题详情 |
| POST | `/api/questions` | 创建题目 |
| PUT | `/api/questions/{id}` | 编辑题目 |
| DELETE | `/api/questions/{id}` | 删除题目 |

**科目相关：**
| 方法 | 路径 | 功能 |
|------|------|------|
| GET | `/api/catalog/subjects` | 列表 |
| POST | `/api/catalog/subjects` | 创建 |
| PUT | `/api/catalog/subjects/{id}` | 编辑 |
| DELETE | `/api/catalog/subjects/{id}` | 删除（级联删除知识点） |

**知识点相关：**
| 方法 | 路径 | 功能 |
|------|------|------|
| GET | `/api/catalog/knowledge-points?subjectId={id}` | 列表（可按科目筛选） |
| POST | `/api/catalog/knowledge-points` | 创建 |
| PUT | `/api/catalog/knowledge-points/{id}` | 编辑 |
| DELETE | `/api/catalog/knowledge-points/{id}` | 删除（若有题目关联则报错） |

#### 核心操作
- 权限检查：所有操作都通过 `UserContext.userId()` 限定当前用户的数据
- 作答状态查询：查询 `answer_record` 表，取每个问题的最新一条记录
- 外键约束：`ON DELETE RESTRICT` 防止删除被引用的科目/知识点

### 3. 考试模块 (ExamController)

#### 功能描述
提供完整的考试流程：出卷、答题、提交、历史记录和详情查看。

#### 业务流程

```
考试完整流程：

1. 出卷（生成试卷）
   ├─ 模式选择：随机 / 知识点 / 错题
   ├─ 参数设置：题目数量、难度范围、时限
   ├─ 题目筛选：
   │  ├─ 随机模式：随机抽取 N 道题
   │  ├─ 知识点模式：从指定知识点随机抽取 N 道题
   │  └─ 错题模式：从错题本中按错误次数排序抽取
   ├─ 数据清理：过滤掉选择题但无选项的脏数据
   ├─ 缓存：题目 ID 列表存入 Redis（30分钟 TTL）
   └─ 返回：试卷 ID + 题目数据

2. 答题（用户作答）
   ├─ 前端缓存试卷到 sessionStorage
   ├─ 单题作答：用户选择或填写答案
   ├─ 实时计时：前端计时，提交时上报
   └─ 无需上报（直到提交）

3. 提交答卷
   ├─ 读取 Redis 中缓存的题目 ID 列表
   ├─ 从数据库查询完整题目数据（避免 Redis 反序列化问题）
   ├─ 逐题批改：
   │  ├─ 单选/多选/判断：字符串比对（答案大小写无关，多选排序后比对）
   │  ├─ 填空/计算：用户填空，状态为 2（待评）
   │  └─ 简答：用户填写，状态为 2（待评）
   ├─ 生成考试记录：
   │  ├─ ExamRecord：试卷名、模式、总题数、正确数、用时、开始/结束时间
   │  ├─ AnswerRecord：逐题记录用户答案、正确状态（1=对、0=错、2=待评）
   │  └─ ErrorBook：自动添加错题到错题本（wrongCount++）
   ├─ 发送 RabbitMQ 消息：触发异步统计更新
   ├─ 删除 Redis 缓存
   └─ 返回：考试成绩

4. 历史记录查询
   ├─ 按 user_id 查询所有 ExamRecord
   ├─ 排序：按创建时间倒序
   └─ 计算正确率、用时等统计

5. 历史详情查看
   ├─ 按 examRecordId 查询 AnswerRecord
   ├─ 批量查询题目信息
   ├─ 组装返回：题干、选项、用户答案、正确答案、作答状态
   └─ 前端渲染：蓝色=答对、红色=答错、绿色高亮正确选项
```

#### 端点列表
| 方法 | 路径 | 功能 |
|------|------|------|
| POST | `/api/exams/generate` | 生成试卷 |
| POST | `/api/exams/submit` | 提交答卷，批改并返回成绩 |
| GET | `/api/exams/history` | 查看历次考试记录 |
| GET | `/api/exams/{id}/detail` | 查看考试详情（每题作答情况） |

#### 核心操作
- **试卷生成**：模式分发、题目筛选、脏数据过滤
- **答卷批改**：多种题型的评分逻辑（自动/待评）
- **缓存策略**：Redis 存题目 ID 列表（避免反序列化）；提交时重新查库获取完整数据
- **错题追踪**：自动在 error_book 中记录错题，下次生成"错题"卷时优先抽取
- **异步处理**：RabbitMQ 消息队列更新 `knowledge_point_stat` 表（学情统计）

### 4. 错题本模块 (ErrorBookController)

#### 功能描述
自动记录用户答错的题目，支持标记重点、记笔记、查看题目详情。

#### 业务流程

```
错题本流程：

1. 自动记录
   ├─ 考试提交时：遍历所有 AnswerRecord
   ├─ 若 correctStatus == 0（答错）
   ├─ 查找或创建 ErrorBook 记录
   ├─ 更新 wrongCount（答错次数）
   └─ 记录 lastWrongTime（最后答错时间）

2. 错题本查询
   ├─ 按 user_id 查询所有 ErrorBook 记录
   ├─ 按 wrongCount 倒序排列（错最多的优先）
   ├─ 批量查询关联的 Question 数据
   ├─ 补充题目信息：题干、题型、选项、答案、解析
   └─ 返回 ErrorBookItem 列表

3. 题目详情查看
   ├─ 弹出 Dialog
   ├─ 显示题干、选项（正确选项绿色高亮）
   ├─ 显示正确答案、解析
   └─ 便于用户复习

4. 标记重点
   ├─ 点击题目行的"重点"开关
   ├─ 更新 ErrorBook.marked 字段
   └─ 用于筛选重点错题

5. 添加笔记
   ├─ 点击编辑笔记
   ├─ 保存到 ErrorBook.note
   └─ 下次查看时显示

6. 移除错题
   ├─ 点击"移除"按钮
   ├─ 删除 ErrorBook 记录
   └─ 不影响 AnswerRecord（历史保留）
```

#### 端点列表
| 方法 | 路径 | 功能 |
|------|------|------|
| GET | `/api/errors` | 查看错题本列表 |
| PUT | `/api/errors/{id}/mark` | 标记/取消标记重点 |
| PUT | `/api/errors/{id}/note` | 编辑笔记 |
| DELETE | `/api/errors/{id}` | 移除错题 |

#### 核心操作
- **自动捕获**：考试提交时自动识别错题，`upsertError()` 逻辑
- **数据聚合**：单次查询返回完整题目信息（题干、选项、答案、解析）
- **排序策略**：按 `wrongCount` 倒序，帮助用户优先复习最容易出错的题

### 5. 背题模式模块 (Study.vue)

#### 功能描述
独立的浏览模式，用户可以逐题查看所有题目及答案，不记录作答，仅用于复习和理解。

#### 业务流程

```
背题流程：

1. 进入背题模式
   ├─ 侧边栏点击"背题模式"
   ├─ 加载所有题目（GET /api/questions）
   ├─ 支持筛选：科目、知识点、题型
   └─ 显示进度：当前题号 / 总题数

2. 题目浏览
   ├─ 左侧显示题目：
   │  ├─ 题干
   │  ├─ 选项（若有）
   │  ├─ 正确答案（绿色高亮）
   │  └─ 解析
   ├─ 实时高亮正确答案（选项中包含该选项字母则高亮）
   └─ 无需作答、无计时

3. 进度追踪（当前会话）
   ├─ 答题卡显示 N 个按钮（1~100...）
   ├─ 灰色 = 未浏览
   ├─ 蓝色 = 已浏览过（当前会话）
   ├─ 点击按钮快速跳转
   └─ 注：关闭浏览器后进度丢失（仅会话级别）

4. 筛选切换
   ├─ 改变科目/知识点/题型筛选
   ├─ 重置题号为 0，清空浏览记录
   ├─ 仅显示匹配的题目
   └─ 便于按知识点专项复习

5. 退出背题
   ├─ 点击"结束学习"按钮
   ├─ 返回首页
   └─ 进度自动清空
```

#### 核心特点
- **纯浏览，不记录**：不生成 ExamRecord、不创建 AnswerRecord、不触发错题
- **即时反馈**：答案直接显示，无需等待批改
- **筛选灵活**：按科目/知识点/题型聚焦复习
- **会话级追踪**：浏览记录存储在前端 JavaScript Set 中，页面刷新后丢失

### 6. 批量导入模块 (ImportController)

#### 功能描述
支持用户通过 Excel 文件批量导入题目到题库。

#### 业务流程

```
导入流程：

1. 上传文件
   ├─ 选择 Excel 文件
   ├─ 可选：指定导入目标（科目 ID / 知识点 ID）
   └─ 点击导入

2. 解析 Excel
   ├─ 读取第一行（表头）
   ├─ 识别列映射：
   │  ├─ 必需列：题目(题干) / 答案 / 题型
   │  ├─ 可选列：难度 / 解析 / 知识点相关
   │  └─ 选项列：按正则 /^(选项|option)[a-zA-Z]$/ 识别
   └─ 无表头或缺少必需列 → 报错停止

3. 数据清洗与转换
   ├─ 逐行处理：
   │  ├─ 题干(stem)：去首尾空白
   │  ├─ 答案(answer)：提取字母（支持 "A/B/C" "A、B、C" "A,B,C" 等格式）
   │  ├─ 题型(type)：验证（single/multiple/blank/judge/short/calculate）
   │  ├─ 难度(difficulty)：缺失则默认 1
   │  ├─ 解析(analysis)：缺失则默认空字符串
   │  ├─ 选项(options)：收集所有选项列，生成 JSON [{key:'A',text:'...'}, ...]
   │  └─ 知识点 ID：若未指定则使用第一个知识点（或提示用户选择）
   └─ 脏数据过滤：单选/多选但无选项 → 跳过（打印警告）

4. 批量插入
   ├─ 逐条插入 Question 表
   ├─ 全量提交事务
   ├─ 任一行失败则全部回滚
   └─ 返回导入统计：成功数 / 失败数 / 错误信息

5. 结果反馈
   ├─ 导入成功：显示"导入成功 N 条"
   ├─ 部分失败：显示"成功 X 条，失败 Y 条，具体错误：..."
   └─ 错误详情：行号 + 错误原因
```

#### 端点列表
| 方法 | 路径 | 功能 |
|------|------|------|
| POST | `/api/import/questions` | 上传 Excel 并批量导入 |

#### 核心操作
- **表头识别**：header-name-based 而非 position-based（题型不一定在第一列）
- **答案提取**：支持多种格式（ABCD、A、B、C、D 等，大小写无关，自动规范化为大写）
- **选项识别**：正则匹配 `选项[a-zA-Z]` 或 `option[a-zA-Z]`，自动排序生成 JSON
- **脏数据处理**：选择题无选项则跳过，防止后续考试出现数据错误
- **事务控制**：一次导入要么全部成功要么全部回滚

### 7. 学情分析模块 (AnalyticsController)

#### 功能描述
统计用户的学习情况，包括掌握度、做题进度等。

#### 业务流程

```
分析流程：

1. 学情概览
   ├─ 统计已做题数 / 总题数
   ├─ 统计总做题次数
   ├─ 统计平均正确率
   ├─ 统计各知识点掌握度：
   │  ├─ knowledge_point_stat 表
   │  ├─ 字段：mastery_degree（百分制）
   │  ├─ 计算：该知识点的考试记录中，correct_count / total_count
   │  └─ RabbitMQ 异步更新
   ├─ 统计错题数 / 已改正数
   └─ 返回 JSON 给前端展示

2. 知识点掌握度排行
   ├─ 查询 knowledge_point_stat
   ├─ 按 mastery_degree 排序
   ├─ 显示：知识点名 + 掌握度 + 最后测试时间

3. 做题进度
   ├─ 统计各题型做题数
   ├─ 统计各难度做题数
   └─ 用于数据可视化
```

#### 端点列表
| 方法 | 路径 | 功能 |
|------|------|------|
| GET | `/api/analytics/overview` | 获取学情概览 |

#### 核心操作
- **异步更新**：RabbitMQ + `StatMessageListener` 实时更新掌握度
- **聚合查询**：从 AnswerRecord 聚合计算各知识点成绩
- **缓存策略**：knowledge_point_stat 表定期更新，避免逐次计算

## 核心业务逻辑总结

### 多种出卷模式的区别

| 模式 | 题目来源 | 排序方式 | 用途 |
|------|--------|--------|------|
| 随机 | 用户所有题目 | 随机打乱 | 综合测试 |
| 知识点 | 指定知识点内的题目 | 随机打乱 | 专项练习 |
| 错题 | 错题本(error_book) | 按错误次数倒序 | 针对性复习 |
| 背题 | 用户所有题目 | 按创建/更新时间 | 浏览学习(不计分) |

### 答题状态标记

| 状态值 | 含义 | 自动判分 | 用途 |
|------|------|--------|------|
| 1 | 答对 | ✓ 单选/多选/判断 | 计入正确计数 |
| 0 | 答错 | ✓ 单选/多选/判断 | 添加到错题本 |
| 2 | 待评 | ✗ 填空/简答/计算 | 用户自评或教师批改 |
| null | 未答 | N/A | 题库显示时的默认状态 |

### 权限与数据隔离

- **用户隔离**：每个表都有 `user_id` 字段，所有查询都加 `WHERE user_id = current_user`
- **跨用户操作防护**：删除/更新前检查归属权，防止越权操作
- **级联删除**：删除科目 → 级联删除其知识点；删除知识点若有题则报错(RESTRICT)

### 缓存与异步

- **Redis 缓存**：试卷 ID 列表（减少序列化问题），30分钟过期
- **异步更新**：考试后通过 RabbitMQ 消息队列异步更新 knowledge_point_stat（掌握度）
- **数据一致性**：提交答卷时重新从 DB 查询题目（不依赖 Redis 对象反序列化）

## 系统约束与边界条件

1. **题目约束**：
   - 选择题（单选/多选）必须有选项，否则生成试卷时过滤掉
   - 填空/简答/计算题无法自动批改，状态为"待评"

2. **错题本约束**：
   - 同一用户对同一题目最多一条错题记录（unique: user_id + question_id）
   - 错题本记录删除后，AnswerRecord 历史保留

3. **时间约束**：
   - JWT token 7天过期
   - Redis 缓存 30分钟过期
   - 考试记录永久保留

4. **删除约束**：
   - 不能删除有题目关联的知识点（ON DELETE RESTRICT）
   - 不能删除有知识点关联的科目（级联删除知识点后再删）

## 总结

该系统通过模块化的功能设计，支持用户完整的学习闭环：
- **输入**：导入题目、自建题库
- **练习**：多种出卷模式自测
- **反馈**：自动批改、错题记录、掌握度统计
- **复习**：背题模式、错题重做、学情分析

核心的技术要点是：异步更新、缓存优化、权限隔离、多种题型支持。
