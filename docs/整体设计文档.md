# 在线刷题系统整体设计文档

## 1. 项目概述

在线刷题系统面向个人学习和备考场景，提供题库管理、科目知识点分类、Excel 批量导入、在线组卷练习、错题本、考试历史和学习数据分析能力。系统采用前后端分离架构，前端负责交互与页面状态管理，后端负责业务规则、数据持久化、鉴权、缓存和异步统计。

## 2. 建设目标

- 建立可长期维护的个人题库，支持按科目、知识点、题型、难度组织题目。
- 支持快速导入已有 Excel 题目资料，降低题库建设成本。
- 支持随机练习、知识点专项练习、错题练习等常见备考模式。
- 通过错题本和知识点掌握度统计，为复习提供反馈依据。
- 通过 JWT、用户数据隔离和统一异常处理保证基础安全性和可维护性。

## 3. 技术架构

### 3.1 前端

- Vue 3 作为页面框架。
- Vite 作为开发和构建工具。
- Vue Router 负责路由与登录守卫。
- Element Plus 提供表单、表格、弹窗、消息提示等基础组件。
- Axios 统一封装请求、JWT 注入、错误提示和 401 跳转。

### 3.2 后端

- Spring Boot 提供 REST API 和应用启动框架。
- Spring Web MVC 实现控制器层。
- MyBatis-Plus 负责实体映射和数据库访问。
- MySQL 存储用户、题目、考试、错题和统计数据。
- Redis 缓存临时试卷题目列表，控制试卷有效期。
- RabbitMQ 承担考试提交后的知识点统计异步更新。
- JWT 实现无状态登录认证。
- Apache POI 实现 Excel 文件解析。

### 3.3 部署形态

开发环境默认端口：

- 前端：`http://localhost:5173`
- 后端：`http://localhost:8000`
- MySQL：`localhost:3308`
- Redis：`localhost:6379`
- RabbitMQ：`192.168.159.128:5672`

## 5. 功能模块设计

### 5.1 用户认证模块

用户注册时写入账号信息并保存密码哈希；登录时校验用户名和密码，成功后签发 JWT。除认证与健康检查外，其他接口都通过拦截器验证 token。前端在登录后保存 token，并在每次请求中自动加入 `Authorization` 请求头。

### 5.2 科目与知识点模块

科目和知识点用于组织题库。科目属于用户，知识点属于科目和用户。系统支持科目、知识点的新增、修改、查询和删除。删除知识点时，如果存在关联题目，后端会通过异常阻止删除，避免题目数据悬空。

### 5.3 题库模块

题目包含题型、题干、选项 JSON、答案、解析和难度。支持按关键词、科目、知识点、题型、难度筛选。题型覆盖单选、多选、判断、填空、简答和计算等类型。查询题目列表时，会附带用户最近一次作答状态，便于前端展示练习反馈。

### 5.4 Excel 导入模块

导入接口接收 Excel 文件，读取第一个工作表，通过表头识别字段，包括科目、知识点、题型、题目、选项、答案、难度和解析。用户可以在页面上指定科目和知识点，也可以让系统根据 Excel 中的科目和知识点名称自动创建目录数据。导入结果返回成功条数、失败条数和错误明细。

### 5.5 组卷考试模块

系统支持三类组卷：

- 随机模式：从当前用户题库中随机抽题。
- 知识点模式：按指定知识点抽题。
- 错题模式：优先从错题本中抽取高频错题。

生成试卷时，后端返回 `paperId` 和题目列表，同时把题目 ID 写入 Redis，有效期 30 分钟。提交答卷时，后端从 Redis 读取试卷题目，计算正确数，写入考试记录和答题记录，并删除试卷缓存。

### 5.6 判分与错题模块

客观题由系统自动判分。多选题会将答案拆分、排序后再比较，避免选项顺序导致误判。简答题和计算题使用用户自评结果。答错的题目会写入错题本；同一题重复答错时增加错误次数并更新时间。用户可以对错题进行标记、备注和删除。

### 5.7 统计分析模块

考试提交后，后端发送消息到 RabbitMQ 队列 `quiz.stat.update`。监听器收到考试记录 ID 后，重建当前用户的知识点统计。统计指标包括作答总数、正确数、掌握度和最近测试时间。前端数据分析页展示题目总数、考试次数、错题数、平均掌握度和知识点统计列表。

## 6. 数据模型

核心表关系：

```text
user_account 1--N subject
subject 1--N knowledge_point
knowledge_point 1--N question
user_account 1--N exam_record
exam_record 1--N answer_record
question 1--N answer_record
question 1--1/N error_book
knowledge_point 1--1/N knowledge_point_stat
```

主要数据表：

| 表名 | 说明 |
| --- | --- |
| `user_account` | 用户账号、密码哈希、邮箱 |
| `subject` | 用户科目 |
| `knowledge_point` | 知识点 |
| `question` | 题目主体 |
| `exam_record` | 考试汇总记录 |
| `answer_record` | 单题作答记录 |
| `error_book` | 错题本 |
| `knowledge_point_stat` | 知识点掌握度 |

更详细的接口说明可参考 `docs/API技术详解文档.md`。

## 8. 安全设计

- 使用 JWT 实现无状态认证，减少服务端会话依赖。
- 业务接口统一从 token 中获取当前用户 ID，避免由前端传入用户 ID。
- 核心查询均带 `user_id` 条件，保证多用户数据隔离。
- 密码使用哈希存储，不保存明文密码。
- 前端收到 401 后清理 token 并跳转登录页。
- 后端通过 CORS 配置限制开发环境允许的前端来源。

## 9. 缓存与异步设计

Redis 用于缓存临时试卷，避免前端提交时篡改题目列表。试卷缓存设置 30 分钟有效期，过期后用户需要重新组卷。

RabbitMQ 用于解耦考试提交和知识点统计重建。提交考试的主流程只负责保存考试结果和发送消息，统计计算由监听器异步执行，降低接口响应时间并提升模块边界清晰度。

## 10. 可扩展方向

- 增加分页查询，优化大题库场景下的题目列表性能。
- 增加题目标签、收藏和复习计划。
- 将统计更新改为增量计算，减少全量重建成本。
- 为导入功能增加模板下载和更严格的数据预校验。
- 增加管理员端，实现公共题库和题目审核。
- 增加单元测试、集成测试和接口自动化测试。

## 11. 已知注意事项

- 当前 `application.yml` 中部分注释和源码中的部分中文错误提示存在编码显示异常，建议后续统一用 UTF-8 修复。
- RabbitMQ 地址当前写死为虚拟机 IP，换环境时需要修改配置。
- 后端 SQL 初始化模式为 `never`，首次部署需要手动执行 `schema.sql`。
