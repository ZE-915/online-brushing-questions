# 题目导入功能设计文档

## 概述

通过 Excel 文件批量导入题目到系统。支持灵活的列格式，基于表头名称智能识别列位置，而非固定列序。

## 整体流程

```
用户选择科目/知识点 → 上传 Excel → 后端解析表头 → 校验必填列 → 逐行解析导入 → 返回结果
```

## 前端设计

### 页面：ImportQuestions.vue

1. **导入设置区域**：科目下拉 + 知识点下拉（级联加载）
2. **上传区域**：拖拽上传，支持 .xlsx/.xls
3. **模板查看**：弹窗展示模板截图
4. **结果展示**：成功/失败条数 + 错误明细表格

### 交互逻辑

- 必须先选择科目和知识点，才能点击上传
- 上传时通过 FormData 携带 `file`、`subjectId`、`knowledgePointId`
- 科目和知识点由页面选择器指定，Excel 中无需包含这两列

### 接口调用

- `GET /api/catalog/subjects` — 加载科目列表
- `GET /api/catalog/knowledge-points?subjectId=X` — 按科目加载知识点
- `POST /api/import/questions` — 上传导入（multipart/form-data）

## 后端设计

### 接口：ImportController

```
POST /api/import/questions
参数：
  - file: MultipartFile（必填）
  - subjectId: Long（选填，页面指定时传入）
  - knowledgePointId: Long（选填，页面指定时传入）
返回：ImportResult { success, failed, errors }
```

### 核心逻辑：ImportService.importExcel()

#### 1. 表头解析（parseHeader）

遍历表头前 30 列，按列名匹配到 ColumnMapping：

| 表头关键词 | 映射字段 | 说明 |
|-----------|---------|------|
| 科目 / subject | subjectCol | 科目列 |
| 知识点 / knowledge / knowledge point | pointCol | 知识点列 |
| 题型 / type / 题目类型 | typeCol | 题型列 |
| 题目 / 题干 / stem / question | stemCol | 题目内容列 |
| 选项A / 选项B / optionA / A / B ... | optionCols | 选项列（可变数量） |
| 正确答案 / 答案 / answer | answerCol | 答案列 |
| 难度 / difficulty | difficultyCol | 难度列 |
| 解析 / analysis / explanation | analysisCol | 解析列 |

**选项列识别规则**：表头匹配 `选项[A-Z]`、`option[A-Z]`、`[A-Z]选项` 或单字母 `A`/`B`/`C` 等，支持任意数量（2-8+个选项）。

#### 2. 列缺失校验

| 缺失列 | 处理方式 |
|--------|---------|
| **题目** | 报错终止："格式错误：缺少题目列" |
| **答案** | 报错终止："格式错误：缺少答案列" |
| **题型** | 报错终止："格式错误：缺少题型列" |
| **科目**（且未通过页面指定） | 报错终止 |
| **知识点** | 不报错，允许为空 |
| **选项列** | 不报错（非选择题可以没有） |
| **难度** | 不报错，所有题目默认难度 1 |
| **解析** | 不报错，所有题目解析为空字符串 |

#### 3. 单元格级别缺失（列存在但某行为空）

| 字段 | 处理方式 |
|------|---------|
| 题目为空 | 跳过该行，不导入 |
| 题型为空 | 默认为 single（单选） |
| 难度为空 | 默认为 1 |
| 解析为空 | 存空字符串 |
| 答案为空 | 存空字符串 |
| 选项为空 | 跳过该选项，不生成对应 JSON 条目 |
| 科目为空（非页面指定模式） | 记录错误，跳过该行 |

#### 4. 科目/知识点指定方式

- **页面指定模式**（推荐）：前端传入 subjectId + knowledgePointId，Excel 无需科目/知识点列
- **Excel 内指定模式**：Excel 含科目列，系统自动查找或创建对应科目和知识点

#### 5. 选项处理

- 选项列数量由表头动态决定，不限于 4 个
- 空白选项不生成 JSON 条目
- 判断题无选项时自动补充 ["正确", "错误"]
- 存储格式：`[{"key":"A","text":"选项内容"}, ...]`

#### 6. 答案标准化（normalizeAnswer）

从答案字符串中提取包含的字母，兼容多种书写格式：

| 用户输入 | 解析结果 |
|---------|---------|
| AC | A,C |
| A,C | A,C |
| A、C | A,C |
| A C | A,C |
| ABCD | A,B,C,D |
| B | B |

逻辑：遍历 A-Z（范围为选项数量），检查答案字符串大写后是否包含该字母。

#### 7. 题型标准化（normalizeType）

| 中文 | 英文 |
|------|------|
| 单选 | single |
| 多选 | multiple |
| 填空 | blank |
| 判断 | judge |
| 简答 | short |
| 计算 | calculate |

## Excel 模板格式

### 格式一：含选项列（单选/多选/判断）

列顺序不限，通过表头名称识别。

**4 选项示例：**

| 题型 | 题目 | 选项A | 选项B | 选项C | 选项D | 正确答案 | 难度 | 解析 |
|------|------|-------|-------|-------|-------|----------|------|------|
| 单选 | 1+1=? | 1 | 2 | 3 | 4 | B | 1 | 略 |

**3 选项 / 5 选项：** 表头写对应数量的"选项X"列即可。

### 格式二：无选项列（填空/简答/计算/判断）

| 题型 | 题目 | 正确答案 | 难度 | 解析 |
|------|------|----------|------|------|
| 判断 | 物质决定意识 | 正确 | 2 | 唯物主义基本观点 |

## 出题过滤（防止脏数据影响）

ExamService 出题时过滤无效题目：

```sql
WHERE user_id = ? AND (
    type NOT IN ('single','multiple')
    OR (options_json IS NOT NULL AND options_json != '[]' AND options_json != '')
)
```

即：选择题必须有非空选项才会被出题，避免格式错误的题目出现在考试中。

---

## Redis 缓存设计

- 出题时 Redis 存储 `List<Long>`（question ID 列表），key 格式：`quiz:paper:{userId}:{paperId}`
- 交卷时从 Redis 取出 ID 列表，再从数据库查询完整 Question 对象
- 避免存储实体类导致的序列化/反序列化兼容性问题（ClassLoader 变化、Jackson 版本等）
- 缓存有效期 30 分钟
